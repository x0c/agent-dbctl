# agent-dbctl Architecture

## 1. Product Positioning & Scope Boundary

`agent-dbctl` is a single-binary local database execution gate, enterprise system/database catalog, and audit console built for both human engineers and coding agents:

- **Agents** interact through the `agent-dbctl` CLI (and companion `SKILL.md`) with non-interactive structured JSON output, automatic workspace-to-system resolution, declarative onboarding (`db add`, `topology apply`, zero-secret Web password handoff), policy/pattern administration, risk preflight, and full auditability.
- **Humans** manage systems, environments, network profiles, credentials, database targets, safety guardrails, production approvals, and audit trails through an embedded TypeScript Web Console served locally on `127.0.0.1` (`go:embed`), or review/complete passwords and execution approvals handed off by agents.
- **Strict Boundary**: `agent-dbctl` forwards queries/commands **verbatim** to each database engine. It does **not** perform cross-dialect SQL translation or ORM-style query rewriting.

### Reference Attribution & Exclusions

The architecture adapts proven mechanisms from three open-source references while explicitly excluding features outside scope:

- **`bytebase/omni` (MIT, Go)**: Adopted the clean split between "reaching the server" (resolved credentials, TLS, custom `Dial`) and "engine protocol conversation" (`Driver`/`Conn`, typed `Value`, `Result.Truncated`, `Plan`), plus engine-aware read/write/DDL/high-cost classification principles across SQL, MongoDB, and Redis. Excluded Bytebase's schema migration/GitOps workflow and any enterprise-licensed modules.
- **`dbward-dev/dbward` (Apache-2.0, Rust)**: Adopted first-class `--preflight` (`EXPLAIN` without `ANALYZE`), `CancellationGuard` (discard dirty pooled connections on timeout/cancel), in-memory TTL `ResultSlot` keeping query payloads out of the audit DB, and tamper-evident SHA-256 hash-chain audit logging. Excluded multi-node remote poll agents and database migration runners (`migrate up/down`).
- **`t8y2/dbx` (Apache-2.0, Rust)**: Adopted strict unidirectional package layering, `manifest.json` + SHA-256 + `host_api_version` verification for external driver plugins, and explicit `doctor`/`capabilities` probes. Excluded JVM/JDBC Java agents (strictly zero JVM), Tauri desktop shells, and CLI override flags (`--allow-writes`/`--allow-dangerous-sql`) so agents cannot self-escalate privileges.

## 2. High-Level Component Architecture

```text
CLI (agent-dbctl) ──[Unix Socket / Loopback RPC]──▶ Local On-Demand Daemon
                                                        │
Web Console (127.0.0.1 HTTP + SSE, go:embed) ───────────┼──▶ Catalog (SQLite WAL)
                                                        ├──▶ Secrets (Keychain / File / Env / Exec)
                                                        ├──▶ NetDial (Direct / SSH Bastion / SOCKS5 / HTTP Proxy)
                                                        ├──▶ Classify + Preflight (SQL / Mongo / Elasticsearch / Redis)
                                                        ├──▶ Policy Engine (4-level monotonic inheritance)
                                                        ├──▶ ApprovalManager (ApprovalProvider: local-web / webhook / extensible)
                                                        ├──▶ Audit (Append-only Hash Chain + ResultSlot)
                                                        └──▶ Driver Execution Plane
                                                               ├── Tier 1 Built-in Pure Go (PG, MySQL, SQLite, ClickHouse, MSSQL, Oracle, Mongo, Elasticsearch, Redis)
                                                               └── Tier 3 External gRPC Subprocess (hashicorp/go-plugin)
```

### Dependency Direction

`internal/types` -> `internal/config` / `internal/secrets` / `internal/netdial` / `internal/classify` -> `internal/driver` -> `internal/store` / `internal/audit` / `internal/policy` / `internal/approval` -> `internal/daemon` -> `internal/cli` / `cmd/*`.

Lower layers never import `daemon` or `cli`.

## 3. Enterprise Database Asset Management (Four-Layer Catalog)

Enterprise environments involve multiple business systems, shared jump hosts, primary/replica topologies, and multi-database instances. `agent-dbctl` models assets in four decoupled layers:

1. **System (`systems`)**:
   - Logical business system (`id`, `slug`, `name`, `owner`, `description`, `tags`, `workspace_paths`, `git_remotes`).
   - `workspace_paths` binds local repository paths (e.g. `~/Codes/order-core`, with `~/` expanded against the active home directory) and `git_remotes` binds portable canonical Git repository identifiers (normalized from HTTPS/SSH/SCP remote URLs by stripping protocol, userinfo/tokens, default ports, and trailing `.git` into `<host[:port]>/<owner>/<repo>`). Both enable `agent-dbctl db list` to automatically prioritize databases belonging to or linked with the agent's current working directory—including Git worktrees, subdirectories, and cross-machine clones—ranking local `workspace_paths` matches ahead of `git_remotes` matches. When `db add` omits `--system` (and `--no-workspace` is false), it first resolves any existing system matching `workspace_paths` or `git_remotes` before falling back to deriving a new slug from the Git repo name or directory basename.
2. **Environment (`environments`)**:
   - Classifications such as `dev`, `staging`, `prod`, each carrying `safety_tier` (`yolo` | `guarded` | `strict`), server-driven localized labels (`en`, `zh`), `#RRGGBB` display color, display order, and `default_policy_id`.
3. **NetworkProfile (`network_profiles`) & CredentialProfile (`credential_profiles`)**:
   - **NetworkProfile**: Reusable connectivity template (`direct`, `ssh_tunnel` bastion, `socks5`, `http_proxy`, TLS mode). Multiple instances share one bastion definition.
   - **CredentialProfile**: Reusable auth definition (`keychain`, `env_ref`, `exec_provider`), `access_level` (`read_only` | `read_write`). Actual secrets live strictly in the OS Keychain (macOS `security -i` over stdin, rejecting whitespace, quotes, and control chars on service/account names), env vars, or shell-free quote-aware external secret-manager commands (`SplitExecArgs`, 64 KiB stdout cap, no secret echo on errors)—never in SQLite or CLI output.
4. **Instance (`instances`) & Target (`targets`)**:
   - **Instance**: Physical/logical endpoint (`engine`, `host`, `port`, `role`: `primary` | `replica` | `standalone`, `primary_instance_id`, `network_profile_id`, cached `capabilities`). Supports live database/schema discovery (`POST /api/v1/instances/{id}/discover` and `agent-dbctl instance discover`) and caches detected `ServerCapabilities` (`capabilities_json`) on successful live probes (omitted from YAML topology exports). Read-only replica routing deterministically selects a matching replica and resolves that replica's own `NetworkProfile` and bastion credentials rather than reusing the primary's network path.
   - **Target**: Logical addressable target (`ref` e.g. `order-core/prod/orders`, short `alias` e.g. `prod-orders`, `owner_system_id`, many-to-many `linked_system_ids`, `instance_id`, `database_name`, `ro_credential_id`, `rw_credential_id`, `policy_override_id`, `status`: `active` | `maintenance` | `disabled`). Targets configured with `ro_credential_id` and no `rw_credential_id` deny mutating/unknown queries at policy evaluation (`credential_missing`), aligning with `TargetSummary.Writable`. Supports concurrent fleet connectivity probing (`agent-dbctl db test --all` / `POST /api/v1/targets/test-all` via bounded 8-worker `Service.PingTargets`). In local mode, `ResolveTarget` fast-paths single-target matches without scanning all targets or triggering Keychain `Has` checks (which remain scoped to `BuildTargetDetails` and credential listing).

### Sanitized Topology Portability & Zero-Secret Onboarding

`GET/POST /api/v1/topology` and `agent-dbctl topology export | apply | schema` export and import `GlobalSecurityConfig` (optional on import), `System`, `Environment`, `NetworkProfile`, `CredentialProfile` metadata (without secrets), `Instance`, `Target`, `Policy`, and `RiskPatternRule` definitions as YAML or JSON so teams and coding agents can share or bootstrap catalog topology and custom high-risk detection rules via Git while keeping credentials local or vault-backed. `ImportTopology` executes inside a single atomic SQLite transaction (validating `schema_version <= 1`, resolving existing entities and cross-entity foreign keys by both ID and natural keys—`Code`/`Slug`/`Name`/`Ref`—with fallback lookup against already-persisted DB rows for partial bundles, preserving local `System.WorkspacePaths` when omitted and preserving `System.GitRemotes` only when omitted as `nil` while applying explicit updates/empty lists, validating all references, and writing a `topology.import` audit entry). `PlanTopologyImport` performs the same validation and natural-key diff read-only for `--dry-run`.

For `keychain` credentials without a stored secret, agents can create the catalog entry with a blank password via `agent-dbctl db add`, `cred set`, or `topology apply` and open the Web Console directly to that credential's password dialog (`--open-secret` or `agent-dbctl ui open --credential <name-or-id>`), letting the human enter the password directly into OS Keychain without exposing it to the agent. Writes validate referenced IDs (`network_profile_id`, `primary_instance_id`, `bastion_credential_id`, `ro_credential_id`, `rw_credential_id`, `linked_system_ids`, `default_policy_id`, `policy_override_id`); deleting referenced `NetworkProfile`, `CredentialProfile`, `PolicyRuleSet`, or primary `Instance` records returns `ErrConflict`, while deleting a `System` or `Target` atomically cleans up unreferenced scoped `policies` and `risk_pattern_rules`.

## 4. Pluggable Drivers, Classification & Policy Engine

### Driver Tiers (Zero JVM)

- **Tier 1 (Built-in Pure Go, `CGO_ENABLED=0`)**: PostgreSQL (`pgx/v5`), openGauss (`openGauss-connector-go-pq`, supporting openGauss RFC5802 SHA256 & SM3 auth), KingbaseES (`gokb`), Dameng DM8 (`gitee.com/chunanyong/dm` thin-mode), TDengine (`net/http` `/rest/sql` REST/JSON transport over `DialContext`/`TLSConfig`), MySQL / MariaDB / TiDB (`go-sql-driver/mysql` via per-connection `mysql.NewConnector`), SQLite (`modernc.org/sqlite`), MongoDB (`mongo-go-driver/v2`), Redis / Valkey (`go-redis/v9`), ClickHouse (`clickhouse-go/v2` via `clickhouse.OpenDB`), Microsoft SQL Server (`go-mssqldb` via `mssql.NewConnectorConfig`), Oracle Database (`go-ora/v2` thin-mode `OracleConnector`), and Elasticsearch / OpenSearch / Easysearch (pure Go `net/http` REST/JSON transport over `DialContext`/`TLSConfig`). Compatible dialect aliases (`postgresql`, `cockroachdb`, `redshift`, `yugabytedb`, `greenplum`, `alloydb`, `highgo`, `uxdb`, `opentenbase`, `kwdb`, `polardb_pg`, `gaussdb`, `gaussdb_dws`, `vastbase`, `mogdb`, `gbase8c`, `kingbase8`, `kingbasees`, `dm`, `dm8`, `taos`, `mariadb`, `tidb`, `oceanbase`, `oceanbase_mysql`, `polardb`, `polardb_mysql`, `tdsql`, `tdsql_mysql`, `goldendb`, `greatsql`, `gbase`, `gbase8a`, `starrocks`, `doris`, `selectdb`, `valkey`, `dragonfly`, `keydb`, `documentdb`, `ferretdb`, `cosmosdb_mongo`, `sqlserver`, `opensearch`, `easysearch`) resolve to their matching built-in driver when no Tier-3 plugin overrides that exact engine key. Drivers adapt across server versions and restricted privilege tiers (e.g., `EXPLAIN` JSON/tree/tabular/SHOWPLAN/XPLAN/`##PLAN_TABLE`/`_validate/query` fallbacks, `transaction_read_only`/`tx_read_only`/`readonly`/`SP_SET_SESSION_READONLY(1)`/`ApplicationIntent=ReadOnly`, `hello`/`isMaster`/`buildInfo` probes, RESP2/RESP3 normalization, and PgBouncer `exec_mode=simple_protocol`).
- **Tier 3 (External gRPC Subprocess Plugins)**: Loaded via `hashicorp/go-plugin` over gRPC (`VersionedPlugins`, supporting both `v1` `Struct` and `v2` typed Protobuf + `Cancel` RPC at `host_api_version: 1..2`) from `<config_home>/plugins/<id>/manifest.json`. Verified against `host_api_version` and binary SHA-256 before execution, with capability-gated host dispatch; crashes are isolated to the subprocess, and daemon-managed network tunnels (`ssh_tunnel`, `socks5`, `http_proxy`) are bridged over an ephemeral authenticated loopback forwarder when `DialContext` is active. See [PLUGIN_PROTOCOL.md](PLUGIN_PROTOCOL.md).

### Connection Lifecycle & Multi-Version Contracts

- **Per-Operation Lifecycle & Cancel Discard**: `Service.openDriverConn` currently resolves credentials and builds a `netdial` dialer per operation (`Ping`, `DiscoverInstance`, `Preflight`, `Execute`, with `Service.Execute` reusing one read-only connection from `Preflight` into `Execute`), wrapping cleanup hooks with `driver.CloseOnce`. On timeout or cancellation, `ExecuteWithCancelGuard` invokes `Conn.CancelAndDiscard()` (including when `ctx.Err() != nil` on the result branch); PostgreSQL issues `CancelRequest`, MySQL issues `KILL QUERY <connection_id>` over a short-lived side connection, and `v2` plugins issue an out-of-band `Cancel` RPC before closing.
- **Engine-Specific Multi-Version & Read-Only Enforcement**:
  - **PostgreSQL**: Builds `pgx.ConnConfig` directly (safe for IPv6 and special database names), supports `exec_mode=simple_protocol` for PgBouncer/proxies, protects `default_transaction_read_only=on` after `Params` when `ReadOnly` is true, queries `SELECT version()` first (fallback `SHOW server_version`) to negotiate dialect (`postgres`, `cockroachdb`, `redshift`, `yugabytedb`, `greenplum`, `alloydb`), skips `EXPLAIN (FORMAT JSON)` straight to text `EXPLAIN` when `!SupportsExplainJSON`, detects `Parallel Seq Scan` / `Foreign Scan` in JSON plans, and implements `SessionResetter` (`PgConn().TxStatus() == 'I'`).
  - **MySQL / MariaDB / TiDB**: Uses `mysql.NewConnector` (avoiding global `RegisterTLSConfig`/`RegisterDialContext` leaks), wraps `driver.Connector.Connect` to enforce `SET SESSION TRANSACTION READ ONLY` -> `tx_read_only = 1` -> `transaction_read_only = 1` on every physical connection (failing closed if all fail), blocks `MultiStatements`/`AllowAllFiles`/`AllowCleartextPasswords` overrides in read-only mode, detects dialect (`mysql`, `mariadb`, `tidb`, `oceanbase_mysql`, `starrocks`, `doris`), fast-paths to tabular `EXPLAIN` when `!SupportsExplainJSON`, parses MySQL v1 JSON, MySQL 8.4 `explain_json_format_version=2`, MariaDB `rows`, and tabular `EXPLAIN` (MySQL 5.5 / TiDB), and implements `SessionResetter`.
  - **SQLite**: Encodes `file:` URIs cleanly, applies `mode=ro` + `query_only(1)` on non-`:memory:` read-only targets (preventing empty file creation on probes), honors allowlisted pragmas, Base64-encodes non-UTF-8 `BLOB` columns, and implements `Dialect`/`ServerCapabilities` + `SessionResetter`.
  - **MongoDB**: Iterates full cursors via `getMore` + `killCursors` cleanup, auto-enables `directConnection=true` when dialing a single host over a tunnel/proxy unless overridden, defaults `ReadOnly` to `SecondaryPreferred`, falls back `Ping` from `buildInfo` to `hello`/`isMaster` with dialect detection (`mongodb`, `documentdb`, `ferretdb`, `cosmosdb_mongo`) and `ListDatabases` to `authorizedDatabases: true`, normalizes `Decimal128`/`Timestamp`/`Regex`/non-finite floats, inspects only `queryPlanner.winningPlan` (unwrapping SBE `winningPlan.queryPlan`, sharded `shards[]`, and aggregation `stages[].$cursor`, ignoring `rejectedPlans`) where `LIMIT` (`0 < limit <= 1000`) -> `COLLSCAN` without blocking stages (`SORT*`, `SHARD_MERGE_SORT`, `GROUP`, `COUNT`, large `SKIP`) is treated as bounded (`FullScan = false`), skips `EXPLAIN` cleanly on `show dbs`/`show collections`, and warns explicitly when `mongosh` syntax is passed instead of JSON RunCommand.
  - **Redis / Valkey**: Uses `redis.NewUniversalClient` (standalone or `cluster=true` / comma-separated seeds, configurable `protocol=2|3`), falls back `Ping` past ACL-restricted `INFO server`, parses `INFO server` dialect banners (`valkey_version:`, `dragonfly_version:`, `keydb_version:`, `redis_version:`) for `ServerCapabilities` (`SupportsRESP3`, `ClusterMode`), normalizes RESP3 `map[any]any` for JSON marshaling, and caps single-command array/map replies via `RowBuffer`.
  - **ClickHouse**: Uses `clickhouse.OpenDB` with native TCP (or `protocol=http`) and custom `DialContext`/`TLSConfig`, probes `SELECT 1` on open and automatically falls back to deadline-stripped cancel-preserving contexts (`context.WithoutCancel` + `context.AfterFunc`) alongside driver-level fail-closed read-only enforcement when the server profile locks `readonly=1`, implements `EXPLAIN ESTIMATE` + `EXPLAIN PLAN indexes = 1` preflight (detecting `ReadFromMergeTree` without `PrimaryKey`/`minmax`/`set`/`bloom_filter` pruning or ClickHouse 24.8 `Condition: true`), introspects `system.tables`/`system.columns`, and cancels active queries via `WithQueryID` + `KILL QUERY WHERE query_id = ... SYNC`.
  - **Microsoft SQL Server (MSSQL / Azure SQL)**: Initializes defaults via `msdsn.Parse("")` + `mssql.NewConnectorConfig` with custom `Dialer` and TLS mapping (preserving self-signed login-packet compatibility under default/`prefer` TLS), sets `ReadOnlyIntent` when `DatabaseName` is specified alongside fail-closed driver read-only checks, introspects `INFORMATION_SCHEMA` + `sys.indexes`/`sys.foreign_keys`, isolates `SET SHOWPLAN_ALL ON` / `SET SHOWPLAN_TEXT ON` preflight to a dedicated `sql.Conn`, and cancels via `KILL <spid>` + close.
  - **Oracle Database**: Uses pure-Go `go-ora/v2` `OracleConnector` with custom `Dialer` and `WithTLSConfig` (supporting both service names and `sid` params), wraps read-only queries in `BeginTx(&sql.TxOptions{ReadOnly: true})` alongside fail-closed driver checks, introspects `all_tables`/`all_views`/`all_synonyms`/`all_tab_columns` (scanning `LONG` `data_default` cleanly and resolving `ALL_SYNONYMS` ownership)/`all_constraints`/`all_indexes`, and runs `EXPLAIN PLAN FOR` + `DBMS_XPLAN.DISPLAY()` preflight (detecting `TABLE ACCESS FULL` and `K`/`M` row estimates, rolling back `PLAN_TABLE`).
  - **Elasticsearch / OpenSearch / Easysearch**: Uses pure Go `net/http` over `DialContext`/`TLSConfig` with Basic, `ApiKey`, or `Bearer` auth, detects `opensearch` / `easysearch` vs `elasticsearch` distribution on `GET /`, lists indices via `/_cat/indices`, flattens nested field mappings via `/<index>/_mapping`, preflights searches via `/_validate/query?explain=true` + `/_count`, executes HTTP+JSON or JSON-shorthand commands with strict read-only filtering, and caps `hits.hits` / array results via `RowBuffer`.
  - **openGauss / GaussDB / Vastbase / GBase 8c**: Uses pure-Go `openGauss-connector-go-pq` configured via `opengauss.ParseConfig` with `postgres://` connector scheme and explicit `DialFunc`/`LookupFunc`/`TLSConfig` injection (`NewConnectorConfig`, bypassing `DialOpen`'s ignored dialer), supporting openGauss RFC5802 SHA256 and national-crypto SM3 authentication alongside MD5, enforces read-only sessions via `SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY` (fallback `SET default_transaction_read_only = on`), detects `opengauss`/`gaussdb`/`vastbase`/`mogdb`/`gbase8c` dialects and `datcompatibility` modes (`PG`/`A`/`B`/`C`), queries `pg_database`/`sys_catalog.sys_database` and `information_schema` without `JOIN LATERAL`, falls back across `public` / `information_schema.tables` during unqualified `DescribeTable` (where `current_schema()` returns `$user` even without a user schema), runs `EXPLAIN (FORMAT JSON)` -> text `EXPLAIN` preflight, and cancels via `CancelRequest` / close.
  - **KingbaseES**: Uses pure-Go `gokb` over custom `DialerContext`/`TLSConfig` (default port `54321`, `kingbase://` scheme; maps empty/`prefer` `TLSMode` to `sslmode=disable` since `gokb` rejects `prefer` and retries once with `sslmode=require` on SSL/`pg_hba` errors), enforces read-only sessions via `SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY` (fallback `SET default_transaction_read_only = on`), falls back `ListDatabases` between `sys_catalog.sys_database` and `pg_catalog.pg_database`, introspects `information_schema` + `pg_indexes`/`sys_indexes`, and runs `EXPLAIN (FORMAT JSON)` -> text `EXPLAIN` preflight.
  - **Dameng DM8**: Uses pure-Go `gitee.com/chunanyong/dm` via bounded slot-pooled `RegisterDialContext` (bridging `DialContext` and `TLSConfig`, keeping raw credentials with explicit query parameters, and retrying once with uppercased `DatabaseName` when case-sensitive `SET SCHEMA` fails with `[-2103]` invalid schema while preserving valid quoted lowercase schemas), enforces read-only sessions via `SP_SET_SESSION_READONLY(1)` / `BeginTx(&sql.TxOptions{ReadOnly: true})` alongside fail-closed driver checks, probes `V$VERSION`, lists schemas via `SYS.SYSOBJECTS`/`ALL_USERS`, introspects `ALL_TABLES`/`ALL_VIEWS`/`ALL_SYNONYMS` (including synonym fallback on `DescribeTable`), and runs read-only-safe `EXPLAIN <sql>` via `sql.Conn.Raw` reading `DmConnection.lastExecInfo.explain` (because `EXPLAIN FOR` fails with `[-6506]: Readonly transaction.` under `SP_SET_SESSION_READONLY(1)` and `##PLAN_TABLE` is absent), falling back to multi-column `EXPLAIN FOR` / text `EXPLAIN` `QueryContext` to detect `CSCN2`/`CSCN`/`SSCN` full scans.
  - **TDengine**: Uses pure-Go `net/http` over `DialContext`/`TLSConfig` against `taosAdapter` (`/rest/sql` and `/rest/sql/<db>`, port `6041`) with Basic or `Taosd` token auth, probes `SELECT SERVER_VERSION()`, lists databases via `SHOW DATABASES`, introspects `SHOW TABLES` / `DESCRIBE <table>`, and preflights reads via `EXPLAIN <sql>`.

### Connection Pooling & Dialect Capabilities

1. **Implemented Primitives (Library & Driver Layer)**:
   - `internal/netdial.TunnelPool`: Keepalive-monitored (`keepalive@openssh.com` with bounded timer) `*ssh.Client` pool keyed by redacted `(network_profile_id, bastion_host, port, user, strict_host_key, sha256(secret))` fingerprint, single-flight dial deduplication, idle TTL eviction, automatic reconnect on dead transport, and `InvalidateProfile` / `InvalidateAll`.
   - `internal/driver.ConnPool`: Read-only `driver.Conn` pool with unconditional write bypass (`!ReadOnly`), SQLite `:memory:` bypass, shorter `ExecProviderMaxAge` (`2m` default; `< 0` disables) for `exec_provider` tokens, `SessionResetter` validation before reuse, permanent poison+discard on `CancelAndDiscard()` or cancelled contexts, `HealthCheckAfter` idle probing, and target/instance/network/credential invalidation.
   - `internal/driver.DetectServerCapabilities`, `types.ServerCapabilities`, `PingResult.Dialect` / `Capabilities`, and `driver.DialectAwareConn` across all 13 built-in drivers.
2. **Daemon Wiring**:
   - `Service` integrates `TunnelPool` and `ConnPool` with catalog-mutation invalidation hooks and cached per-instance `ServerCapabilities` updates (`Shutdown()` drains both pools cleanly).

### Risk Classification, Normalized Context & Preflight

- **Multi-statement safety**: Multi-statement SQL scripts are split respecting quotes, dollar-quotes, comments, and MySQL conditional comments; overall classification takes the maximum severity across all statements.
- **Fail-closed unknown syntax**: Unrecognized syntax is classified as `unknown` (`high_risk`), which still runs under `dev` (`yolo`) if allowed, but forces human approval under `guarded`/`strict` environments.
- **Hardened high-cost & dangerous read detection**:
  - **SQL**: missing `LIMIT` / `WHERE`, unbounded `SELECT *` without `WHERE` or bounded `LIMIT` (`<= 1000`), `TABLE <tbl>` shorthand without `LIMIT`, `CROSS JOIN` & implicit comma joins (`FROM a, b`), `WITH RECURSIVE`, `ORDER BY RAND()/RANDOM()`, `SQL_CALC_FOUND_ROWS`, deep `OFFSET >= 10000`, locking reads (`FOR UPDATE`/`FOR SHARE`/`FOR NO KEY UPDATE`/`FOR KEY SHARE`/`LOCK IN SHARE MODE`), `EXPLAIN` & `EXPLAIN ANALYZE` inner-DML propagation (preserving `IsReadOnly = false` when analyzing DML/admin so `prod_read_only_freeze` still blocks it), lexical `RETURNING` detection across PostgreSQL and SQLite, SQLite parenthesized `PRAGMA fn(...)` allowlisting (`table_info`, `table_xinfo`, `index_list`, `index_info`, `index_xinfo`, `foreign_key_list` safe-read; mutating pragmas like `query_only(0)`/`wal_checkpoint` elevated to `admin`), and dangerous scalar/side-effect calls even without `FROM` (`pg_read_file`/`lo_export`/`dblink`/`load_extension` as `admin`, `nextval`/`setval`/`pg_advisory_lock`/`get_lock` as `write`, `pg_sleep`/`sleep`/`benchmark`/`randomblob`/`zeroblob`/`generate_series`/`xmlparse` as `high_cost_read`).
  - **MongoDB**: recursive operator scanning (`$where`, `$function`, `$accumulator`, `$lookup`/`$graphLookup`, `allowDiskUse`, `noCursorTimeout`, unanchored `$regex`), write stages (`$out`/`$merge`), and `explain` verbosity/inner-query checks (`executionStats`/`allPlansExecution`).
  - **Redis / Valkey**: subcommand allowlisting for `CLIENT` (`ID`/`GETNAME`/`INFO` safe; `LIST` high-cost; `PAUSE`/`KILL`/others admin) and `MEMORY` (`STATS`/`MALLOC-STATS`/`DOCTOR` safe; `USAGE ... SAMPLES 0` high-cost; `PURGE`/others admin), bounded `SCAN`/`ZRANGEBYSCORE`/`GEOSEARCH` count checks, and blocking list/stream commands.
- **Cross-Engine Schema Introspection (`driver.SchemaInspector`)**: All 13 built-in drivers implement read-only `ListTables` and `DescribeTable` (`db schema <ref> [table]`), enumerating SQL tables/views/synonyms/supertables/columns/indexes/foreign keys (PostgreSQL, openGauss, KingbaseES, Dameng DM8, TDengine, MySQL, SQLite, ClickHouse, MSSQL, Oracle), MongoDB collections/indexes/sampled document fields, Elasticsearch/OpenSearch/Easysearch indices/flattened mappings, and Redis bounded `SCAN` key-prefix patterns & types under target read-only credentials with audit logging (`schema.list` / `schema.describe`).
- **Normalized `QueryContext` extraction**: `classify.ExtractQueryContext` exposes comment-stripped/literal-redacted text, parsed SQL tokens/functions/tables/pragmas, parsed Redis command vectors, and parsed MongoDB JSON documents/operators for downstream pattern evaluation.
- **Preflight (`EXPLAIN` without `ANALYZE`)**: In `guarded`/`strict` environments (or when an active `preflight_metric` pattern rule applies), safe reads—and best-effort single-statement DML (`INSERT`/`REPLACE`/`UPDATE`/`DELETE`/`MERGE`) when not frozen—undergo non-mutating `EXPLAIN` preflight before execution or approval submission; full scans (`Seq Scan`, `ALL`, uncapped MongoDB `COLLSCAN`, SQLite `SCAN`—excluding bounded MongoDB `LIMIT (<= 1000) -> COLLSCAN` without blocking stages) or estimated rows exceeding `explain_max_rows` escalate to `require_approval`, attaching the plan summary to the approval card. See [READ_RISK_AUDIT.md](READ_RISK_AUDIT.md) for empirically verified high-risk read patterns.

### Four-Level Monotonic Policy Inheritance & Custom High-Risk Patterns

Effective policy resolves monotonically in order: `GlobalSecurityConfig` -> `Environment` -> `System` (`OwnerSystem` + `LinkedSystems`) -> `Target`.
Lower levels can **tighten** restrictions monotonically across both numeric ceilings (shorter timeout, lower row/byte cap, lower `explain_max_rows`) and boolean guardrails (`AllowSafeRead`, `RequireApprovalOn*`, `AllowMultiStatement`, with provenance tracked in `Sources`)—validated via `ValidateRuleSet` and `ValidateGlobalConfig`—but never exceed global hard upper bounds or override `prod_read_only_freeze`. Scoped policies can also configure `ScanReadMode` (`allow` | `reason_only` | `require_approval`, defaulting to `allow` in `yolo` and `require_approval` in `guarded`/`strict`): setting `reason_only` on a target (`db set <ref> --scan-read-mode reason_only`) or env/system lets safe full-scan reads (`EXPLAIN` full scan / row-threshold hits without matched custom risk patterns) execute immediately when `--reason` is supplied while failing fast with `reason_required` when `--reason` is omitted. Both `PolicyRuleSet` and `RiskPatternRule` apply monotonically across `OwnerSystem` and all `LinkedSystems`, accept ID or canonical code/slug/ref matching consistently, and canonicalize known scope references on write. `DisplayCatalog.ApprovalProviders` is populated dynamically from the daemon's active `ApprovalManager` providers.

- **Configurable High-Risk Pattern Rules (`RiskPatternRule`)**: Layered atop the built-in classifier across `global -> env -> system -> target` scopes, filtered by target engine/family. Lower scopes can add rules or tighten actions (`elevate_high_cost -> require_approval -> deny`) and enrich confirmation copy/provider overrides, but cannot disable or weaken an enabled ancestor rule. Rules persist in SQLite (`risk_pattern_rules`) with same-transaction hash-chain audit logging and `/api/v1/topology` + CLI (`security`, `policy`, `pattern`) management; execution approvals remain human-only.
- **Multi-Modal Composable Matchers**: Rules compose `all` / `any` / `not` conditions over 8 matcher types: `function_call`, `table_ref`, `pragma_name`, `command_arg`, `json_path`, `regex` (Go RE2 with AST node & length limits, cached in a bounded `1024`-entry map after validation, defaulting to comment-stripped normalized queries), `risk_flag`, and `preflight_metric`.
- **Secondary Confirmation & Dry-Run Sandbox**: Matched `require_approval` rules force human approval even in `dev` (`yolo`) targets, surfacing structured `MatchedRule` details (`confirm_title`, `confirm_message`, `matched_fragment`, scope, action) in CLI JSON/hints, Web UI approval cards, webhooks, and `audit_logs`. The Web Console and CLI include 11 official preset rule packs (`pg-side-effect`, `sqlite-pragma-blob`, `redis-single-thread`, `mongo-js-explain`, `mysql-dos-guard`, `clickhouse-heavy-scan`, `mssql-proc-dos`, `oracle-sys-guard`, `dameng-sys-guard`, `tdengine-tsdb-guard`, `es-unbounded-scan`) and an offline dry-run test sandbox (`POST /api/v1/risk-patterns/test` and `agent-dbctl pattern test`).

## 5. Pluggable Approval Abstraction (`ApprovalProvider`)

Approval workflow is decoupled behind `internal/approval.Provider`:

- **Built-in `local-web` provider**: Persists an approval record with a cryptographic one-time `approval_token` (stored hashed), broadcasts an SSE event, and opens `http://127.0.0.1:<port>/approvals/<id>?token=<token>` in the local browser (suppressed when `AGENT_DBCTL_NO_BROWSER=1`). `SanitizeTicketURL` strips `?token=` before persisting `external_ticket_url` in SQLite. When `GlobalSecurityConfig.RequireReasonForApproval` is enabled (default `true`), operations that resolve to `require_approval` reject blank `Reason` submissions immediately with `reason_required` before opening an approval ticket so human reviewers always receive context.
- **Built-in `webhook` provider**: Enabled via `AGENT_DBCTL_WEBHOOK_URL` (`https://` required for remote hosts; `http://` restricted to loopback), optional HMAC-SHA256 signing (`AGENT_DBCTL_WEBHOOK_SECRET` -> `X-Agent-DBCTL-Timestamp` + `X-Agent-DBCTL-Signature`), and `AGENT_DBCTL_WEBHOOK_TIMEOUT` (`5s` default, `30s` max). Posts redacted `approval.requested` (with token-free `review_url`) and `approval.cancelled` JSON payloads and accepts optional `{ticket_id, ticket_url}` fields from 2xx responses.
- **Lifecycle & restart recovery**: `ResolveApproval` enforces wall-clock expiry atomically (committing `expired` + audit row and returning `ErrApprovalExpired`); deadline watchers use `time.NewTimer` + stop/done channels for immediate daemon shutdown; `RecoverOnStartup` reconciles interrupted `running`/`pending` operations on daemon startup as `failed` (`daemon_restarted`, `retryable = is_read_only`), expires overdue approvals, and rehydrates still-valid pending approvals via `Manager.Rehydrate`.
- **Enterprise extensibility**: External approval flows (Feishu, WeCom, Slack, internal ticket APIs) implement `ApprovalProvider` (`Submit`, `Cancel`, external status sync), while fully air-gapped DMS platforms can be integrated as Tier-3 `Driver` plugins—preserving the exact CLI (`--wait=false` + `op status`/`op wait`) and audit contract.

## 6. Audit Integrity, Result Isolation & Security

- **SQLite WAL, `0600` Mode & Hash Chain**: `~/.config/agent-dbctl/agent-dbctl.db` (dir `0700`, explicit Unix `os.Chmod(dbPath, 0o600)` in `store.Open`) enables `PRAGMA journal_mode=WAL` and `busy_timeout=5000`, verified via readback on open; `store.Open` fast-paths already-migrated schema v6 databases after confirming `schema_migrations` and `operation_results` exist, skipping redundant DDL and `PRAGMA table_info` probes. SQLite triggers forbid `UPDATE` and `DELETE` on `audit_logs`. Multi-engine lexical/JSON `RedactQuery` scrubs SQL literals, dollar-quotes, password clauses, URI credentials, Redis `AUTH`/`ACL SETUSER`/`CONFIG SET`, and MongoDB literal values (preserving collection names and `$` operators) before persistence. Each audit row chains `prev_hash` + `entry_hash` (SHA-256) and records `actor`, `action`, `target_id`, `operation_id`, `payload_json`, and `created_at_utc`.
- **In-Memory `ResultSlot`**: Query rows are streamed up to `max_rows` / `max_bytes` on complete row boundaries, stored in a bounded memory cache (`maxSlots = 64`, `maxTotalBytes = 32 MiB`, oldest-entry eviction) with wall-clock TTL (`time.Now().Round(0)`), and never dumped into `audit_logs`.
- **Hardened Local Web Guard (Host + Same-Origin + Per-Session Cookie/CSRF)**: All Web HTTP requests pass `WebSecurityMiddleware`, which rejects non-loopback `Host` headers (`127.0.0.1`, `localhost`, `[::1]`) to block DNS rebinding. `GET /api/v1/bootstrap` issues a per-daemon cryptographic `HttpOnly; SameSite=Strict` session cookie (`agent_dbctl_session`) alongside an in-memory `ui_csrf_token`. Every mutating local HTTP endpoint (`POST`/`PUT`/`DELETE`/`PATCH`) enforces strict browser same-origin checks (`Origin`, `Sec-Fetch-Site`, `Referer`—headerless loopback requests are rejected) and requires matching session cookie + `X-Agent-DBCTL-CSRF` header (except `POST /api/v1/approvals/{id}/approve|reject`, which accept either a valid UI session+CSRF or a valid one-time `approval_token`). Programmatic local automation uses the private `0600` daemon RPC channel via `agent-dbctl` CLI rather than `/api/v1/*`.
- **Zero-Runtime-CDN Embedded Web Console**: `web/` bundles React, Lucide icons, Tailwind CSS v4, and `@x0c/ui` (sourced from its public GitHub Release tarball with lockfile integrity) via Vite 8 Rolldown vendor `codeSplitting` chunks (`web/vite.config.ts`) and embeds the compiled static assets directly via `go:embed` (`internal/webui`), requiring no private registries or runtime CDNs. The Web Console defaults to the browser's locale (`zh` / `en`) and composes `@x0c/ui`'s `AppTopbar`, `CommandPalette`, `AppFrame`, `SideNav`, `DropdownMenu`, and `UserAvatar`: the topbar keeps only the `⌘K` command trigger and, in server mode, a single circular `UserAvatar` account menu housing user identity, locale switch (`agent-dbctl.locale.v1` synchronized with server-driven `DisplayCatalog` labels), and Sign Out (while local mode keeps a compact language trigger), placing version/non-default session metadata quietly in the `SideNav` footer. Unauthenticated browser visits auto-redirect straight to OIDC SSO when enabled (with anti-loop guards for explicit sign-out, `?local=1`, `?error=`, and 15s session attempts), and live tab/SSE mounts wait for `/api/v1/bootstrap` confirmation even when frame-0 catalog state is hydrated synchronously from cache. The `Systems & Databases` surface focuses primary tabs on `Databases` and `Systems`, provides a one-shot `Add Database` flow (`POST /api/v1/db/add`, mirroring CLI `db add` to converge System/Credential/Instance/Target in one step), tucks reusable `Instances`, `Networks`, and `Credentials` templates into a secondary `Resources` drawer (preserving `/catalog?subtab=...` deep links), and houses `Environments` under `Policies & Guardrails`.

## 8. Dual-Mode Client/Server Architecture (`local` vs `serve` + `remote`)

`agent-dbctl` ships as a single binary supporting both zero-config **Local Mode** (default) and centralized enterprise **Client/Server Mode** (`agent-dbctl serve` + remote CLI contexts) sharing one `Service` core:

```text
Local Mode (default):
  CLI ──[Unix Socket / 0600 Loopback]──▶ Local Daemon (local-owner, SQLite WAL, OS Keychain)
                                           └── Embedded Web Console (127.0.0.1)

Remote C/S Mode:
  Agent/Dev CLI ──[HTTPS + Bearer/OIDC + optional mTLS]──┐
                                                         ▼
  Human Browser ──[HTTPS + OIDC/Session + CSRF]────────▶ Reverse Proxy ──▶ agent-dbctl serve (1..N)
                                                                             ├── AuthN & RBAC Middleware
                                                                             ├── Encrypted Vault / Allowed Exec/Env
                                                                             ├── TunnelPool + ConnPool
                                                                             └── Repository (SQLite WAL | PostgreSQL)
                                                                                   + ResultSlot / PubSub (Memory | PG | Redis)
```

### Context & Transport Separation

- **Named Contexts (`~/.config/agent-dbctl/contexts.yaml`, `0600`)**: Holds `current_context` (`local` default or named remote contexts with `endpoint`, `ca_cert_file`, `client_cert_file`, `client_key_file`, `auth_mode`, and `insecure_skip_tls_verify`). Remote tokens live in OS Keychain / `0600` secret storage under `ctx:<name>`, never inside `contexts.yaml`.
- **HTTPS Enforcement**: Non-loopback remote endpoints strictly require `https://`. Environment overrides (`AGENT_DBCTL_CONTEXT`, `AGENT_DBCTL_ENDPOINT`, `AGENT_DBCTL_TOKEN`) allow headless CI/agent containers to connect without modifying `contexts.yaml`.
- **Cross-Machine Workspace Matching**: Remote clients forward local `cwd` and normalized `git_remotes`; remote servers rank targets primarily by `System.GitRemotes` across developer workstations.

### Unified Principal, AuthN & Four-Scope RBAC

- **Unified `Principal`**: Every request resolves to a `Principal` (`local_owner`, `human`, or `agent_token`) carrying `ID`, `Subject` (`user:<email>` or `agent:<owner>:<token_name>`), `OwnerUserID`, `Roles`, and token scope ceilings, replacing static `"agent-cli"` / `"web-admin"` strings in `operations`, `approvals`, and `audit_logs`.
- **Web Authentication**: Supports configurable OIDC (Authorization Code + PKCE, consuming `oidc_auth_states` and preserving deep-link `return_to` across provider `?error=` redirects while enforcing safe `return_to` paths and rendering an explicit retry state if `bootstrap` fails with a non-401 error) and Argon2id local username/password sessions persisted in `web_sessions` (`Secure; HttpOnly; SameSite=Lax` cookies + per-session CSRF token). `ConsumeOIDCAuthState` uses `FOR UPDATE` (PostgreSQL) and `RowsAffected` checks to prevent concurrent replay. `WebSecurityMiddleware` validates configured `PublicURL`/`AllowedHosts` and strict same-origin headers in server mode while keeping loopback enforcement in local mode.
- **CLI / Agent Authentication**: Supports OIDC Device Flow (`agent-dbctl login`, RFC 8628) and revocable API Tokens (`adb_live_<prefix>_<secret>`, stored as SHA-256 hashes in `api_tokens` with an explicit `principal_kind` column). Interactive CLI logins (`cli-sso` / `cli-web`) mint `PrincipalHuman` tokens carrying the user's full RBAC bindings (excluding web-only CSRF approval resolution routes), and `agent-dbctl logout` revokes that caller token on the server via `POST /rpc/v1/auth/logout` before removing local context credentials; tokens issued via `/api/v1/tokens` retain `PrincipalAgentToken` scope ceilings and restrictions. Background `last_used_at_utc` updates run under `Service.goBackground` + `CancelBackground()`, while `Execute` cancels pending approvals cleanly if shutdown has already begun (`goBackground == false`). `filterEventForPrincipal` resolves `SystemID` and checks `PrincipalID` on `approval_resolved` SSE events, and `invalidateLocalPools` invalidates `TunnelPool` profiles on `"network"` / `"network_profile"` mutations.
- **Role Matrix (`platform_admin`, `system_admin`, `approver`, `developer`, `viewer`)**: Scoped across `global`, `system`, and `env`. RBAC composes orthogonally with the 4-level monotonic Policy Engine and RiskPattern rules (strictest decision wins):
  - **Human-Only Boundaries**: `PrincipalAgentToken` is denied `ActionApprovalResolve`, `ActionUserManage`, `ActionGlobalSecurityWrite`, `ActionEnvWrite`, `ActionPluginManage`, `ActionCredentialExecWrite`, and `ActionTopologyWrite`. `POST /api/v1/approvals/{id}/approve|reject` requires `Principal.Kind` to be `human` or `local_owner` plus `approver` RBAC on the target's `System` and `Environment`—never `agent_token`. `AdminApplyTopology` additionally enforces `ActionGlobalSecurityWrite` and `ActionEnvWrite` when importing global security or environment definitions, while target test, pattern dry-run, `PingInstance`/`DiscoverInstance` (blocking non-admin probing on global instances or cross-system credentials), and keyset `BeforeSeq` audit pagination filter consistently in server mode.
  - **Four-Eyes Separation (`forbid_self_approval`)**: Enforced directly inside `rbac.AuthorizeApprovalDecision` (covering `app.PrincipalID` populated by `approval.Manager.Submit`, `op.OwnerUserID`, and `app.Actor`), enabled by default in server mode so an approver cannot approve operations initiated by themselves or by an `agent_token` they own.

### Server-Side Secrets, Egress Guardrails & Storage Dual Backend

- **Envelope-Encrypted Server Vault (`EncryptedStore`)**: Server mode encrypts stored database/bastion secrets with per-record 256-bit DEKs (AES-256-GCM) wrapped by an external KEK (`AGENT_DBCTL_MASTER_KEY` or key file, supporting `key_version` rotation), persisted either in `encrypted_secrets` (DB) or an encrypted file store.
- **Server Egress SSRF & RCE Guardrails**: Server mode enables `DialPolicy.EnforceEgressGuard` by default across Direct, SOCKS5, HTTPProxy, and SSHTunnel/`TunnelPool` connections (plus Tier-3 plugin subprocesses via `NeedsDialBridge`), parsing connect addresses via `netip` (stripping IPv6 zone IDs and unmapping IPv4-mapped IPv6), failing closed on unparseable/DNS-failed hosts, blocking loopback/metadata hostnames and locally-resolvable blocked targets even behind proxy/tunnel profiles, blocking loopback, link-local metadata, CGNAT (`100.64.0.0/10`), broadcast/reserved (`240.0.0.0/4`), and NAT64 (`64:ff9b::/96`) ranges unless exempted by `allowed_egress_cidrs`, and disabling HTTP 30x redirects in HTTP-based drivers. `exec_provider` and `env_ref` credentials can only be created by `platform_admin` matching configured allowlists.
- **Dual Repository (`sqlite` | `postgres`)**: `internal/store.Repository` supports SQLite WAL (local & single-node server) and PostgreSQL (`pgx/v5`) for multi-replica deployments. SQLite serializes both transactional writes and standalone writes (including asynchronous token/session maintenance) through one store-level writer lock so a standalone commit cannot invalidate a deferred transaction's read snapshot with `SQLITE_BUSY_SNAPSHOT`. PostgreSQL serializes `audit_logs` hash-chain appends via `SELECT ... FOR UPDATE` on `audit_chain_head` (re-selecting `FOR UPDATE` after cold-start `ON CONFLICT(id) DO NOTHING`), enforces `BEFORE UPDATE OR DELETE` immutability triggers, and coordinates cross-replica approval wakeups, operation cancellations, and SSE fan-out via `EventBus` (`memory` | `postgres` `LISTEN/NOTIFY` | `redis`) and `ResultSlot` (`memory` | `redis`), with `owner_node_id` + `lease_expires_at_utc` preventing multi-node startup recovery races.
- **Containerized Server Packaging & Host Allowlist Ordering**: [Dockerfile](../Dockerfile), [compose.yaml](../compose.yaml), and [deploy/server.yaml.example](../deploy/server.yaml.example) provide a non-root multi-stage build (`node:22-alpine` + `golang:1.26-alpine` + `alpine:3.21`) wired to `postgres:16-alpine` and password-protected `redis:7-alpine` (`--requirepass` via `AGENT_DBCTL_REDIS_PASSWORD`), plus an optional `--profile tls` Caddy ingress ([deploy/Caddyfile.example](../deploy/Caddyfile.example)). Note that `ServerSecurityMiddleware` validates the effective `Host` header against `EffectiveAllowedHosts()` **before** exempting `GET /healthz`, so reverse-proxied or containerized deployments using `public_url: https://...` must keep loopback hosts (`127.0.0.1` / `127.0.0.1:8080`) in `allowed_hosts` for internal container `HEALTHCHECK` probes to succeed. Root-anchored patterns in [.dockerignore](../.dockerignore) (`/agent-dbctl`) prevent BuildKit from excluding nested directories such as `skills/agent-dbctl/`.
