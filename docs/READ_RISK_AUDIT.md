# Read-Query Risk Matrix and Guardrail Audit

Empirical audit of dangerous or high-load read and operational patterns across PostgreSQL (verified on 18.6), openGauss (live-verified on container image), KingbaseES, Dameng DM8 (live-verified on DM8), TDengine (live-verified on 3.4.3.9), SQLite (verified on 3.50.6), MySQL (8.0+), MongoDB, Elasticsearch / Easysearch (live-verified on 1.8.3), and Redis/Valkey, alongside audited `agent-dbctl` classifier, preflight, and policy-gate coverage, implemented remediations, and remaining boundaries.

## 1. Cross-Engine Read Hazard Categories

1. **Execution disguised as diagnostics**:
   - PostgreSQL / openGauss / KingbaseES / MySQL `EXPLAIN ANALYZE <DML>` executes the statement and mutates rows unless wrapped in an explicit rolled-back transaction.
   - MongoDB `explain` with `verbosity: "executionStats"` or `"allPlansExecution"` executes the query and any `$function`/`$accumulator` JavaScript (only `"queryPlanner"` is metadata-only).
   - Easysearch `_sql/_translate` accepts embedded SQL payloads and must delegate classification to `classifySQL` just like `/_sql`.
2. **Side effects permitted inside read-only sessions**:
   - PostgreSQL `default_transaction_read_only = on` still allows `pg_advisory_lock()`, `pg_sleep()`, and server-file reads (`pg_read_file()`, `pg_ls_dir()`) when the role has privileges (`SUPERUSER` / `pg_read_server_files`).
   - KingbaseES exposes `sys_*` aliases (`sys_read_file`, `sys_read_binary_file`, `sys_ls_dir`, `sys_stat_file`, `sys_sleep`, `sys_advisory_lock`, `sys_terminate_backend`) alongside `pg_*`; openGauss exposes `gs_roach_*` backup/WAL controls, `gs_wlm_*` resource-pool/cgroup mutators (`gs_wlm_readjust_*`, `gs_wlm_rebuild_*`, `gs_wlm_switch_*`, `gs_wlm_node_*`), `gs_password_notify`, and `pgxc_*` cluster controls.
   - Dameng DM8 permits `SELECT <func>() FROM DUAL` calls to parameter/job/external-IO procedures (`SF_SET_SYSTEM_PARA_VALUE`, `SP_CREATE_JOB`, `DBMS_XMLGEN`, `UTL_FILE`, `UTL_HTTP`, `DBMS_SQL`, `DBMS_LOCK.SLEEP`).
   - SQLite `PRAGMA query_only = 1` does not block `PRAGMA query_only(0)` (function-style syntax resets it to `0`), `PRAGMA wal_checkpoint(TRUNCATE)`, `PRAGMA integrity_check`, or `ATTACH DATABASE`.
3. **Read-induced lock cascades and WAL starvation**:
   - PostgreSQL / openGauss long-running `SELECT` holds `ACCESS SHARE`; a queued `ALTER TABLE` (`ACCESS EXCLUSIVE`) then blocks all subsequent queries—including indexed primary-key lookups—behind it in the FIFO lock queue.
   - SQLite unclosed read transactions pin WAL read marks and block `PRAGMA wal_checkpoint(TRUNCATE)` (`busy=1`), causing `-wal` growth.
   - Locking reads: `FOR UPDATE`, `FOR SHARE`, `FOR NO KEY UPDATE`, `FOR KEY SHARE`, `LOCK IN SHARE MODE`.
4. **CPU / memory / I/O amplification**:
   - `TABLE <tbl>` shorthand (PostgreSQL / MySQL 8.0.19+), implicit comma joins (`FROM a, b`) without join predicates, unbounded `WITH RECURSIVE`, Oracle/Dameng `CONNECT BY` hierarchical row generation (`SELECT LEVEL FROM DUAL CONNECT BY LEVEL <= ...`), large generators (`generate_series`), SQLite `randomblob()` / `zeroblob()`, `ORDER BY random()` / `RAND()`, deep `OFFSET`, and `SELECT` with `WHERE` but no `LIMIT`.
   - TDengine unbounded super-table `SELECT` without `WHERE`/`ts` bounds, `COMPACT`, `FLUSH DATABASE`, `RESET QUERY CACHE`, `KILL QUERY|CONNECTION|STREAM`, and native C UDF registration (`CREATE FUNCTION`).
   - MySQL `SLEEP()`, `BENCHMARK()`, `LOAD_FILE()`, `GET_LOCK()`, `SQL_CALC_FOUND_ROWS`, and `REGEXP` (mitigated in 8.0+ by ICU `regexp_time_limit`, Error 3699 if exceeded).
   - MongoDB `$where`, `$function`, `$accumulator`, unanchored/case-insensitive `$regex`, unindexed `$lookup` / unbounded `$graphLookup`, `countDocuments({})`, `distinct`, `allowDiskUse: true`, `noCursorTimeout`.
   - Elasticsearch / Easysearch painless scripts, unscoped cross-index searches, `scroll`, `size > 1000`, deep `from >= 10000`, and heavy vector `knn` scans (`k > 100` or `num_candidates > 1000`).
   - Redis/Valkey single-thread stalls: `CLIENT PAUSE`, `MEMORY USAGE <key> SAMPLES 0` ($O(N)$ nested scan), huge `SCAN ... COUNT`, `EVAL_RO`/`FCALL_RO` loops, `KEYS`, `HGETALL`/`SMEMBERS`/`LRANGE 0 -1`, `SORT_RO ... BY ... GET`, large-radius `GEORADIUS`/`GEOSEARCH`, `MONITOR`, `XREAD BLOCK 0`.
5. **`EXPLAIN` planner blind spots**:
   - PostgreSQL `EXPLAIN` reports `MaxPlanRows=31, Cost=3.35, FullScan=false` on a 1,000,000-row `WITH RECURSIVE` query, and `Node=Result, MaxPlanRows=1, FullScan=false` on `SELECT pg_sleep(...)` / `pg_advisory_lock(...)`.
   - Dameng DM8 `EXPLAIN SELECT LEVEL FROM DUAL CONNECT BY LEVEL <= 10000000` (live-verified on DM8) reports `#HIERARCHICAL QUERY: [1, 1, 1]` (`EstimatedRows=1`), while `FROM DUAL` previously triggered the scalar-DUAL safe-read bypass unless `CONNECT BY` is explicitly detected.
   - SQLite `EXPLAIN QUERY PLAN` reports `SCAN CONSTANT ROW` (not a table `SCAN`) for `randomblob(200000000)`.

## 3. Remediation Status (Built-in Hardening & Custom High-Risk Pattern Layer)

- **Built-in Classifier & Context Extraction (`internal/classify/`)**: Hardened SQL (`EXPLAIN`/`EXPLAIN ANALYZE` inner-DML propagation preserving `IsReadOnly=false`, parenthesized `PRAGMA` allowlist, dangerous/side-effect scalar functions even without `FROM` including Kingbase `sys_*`, openGauss `gs_*`/`pgxc_*`, Dameng `SF_*`/`SP_*`/`DBMS_*`, `CONNECT BY` hierarchical detection, `FOR KEY SHARE`, `TABLE` shorthand, implicit comma joins, `WITH RECURSIVE`, `ORDER BY RAND()/RANDOM()`, `SQL_CALC_FOUND_ROWS`, deep `OFFSET`, TDengine `COMPACT`/`RESET`), MongoDB (`explain` verbosity & inner-query analysis, recursive nested operator detection), Elasticsearch/Easysearch (`_sql`/`_sql/_translate` delegation and `script`/`scroll`/`knn` scan flags), and Redis/Valkey (`CLIENT` & `MEMORY` subcommand allowlisting, `SCAN` count bounds, range/geo/fanout/blocking guards), alongside normalized `QueryContext` extraction.
- **Custom High-Risk Pattern Engine (`internal/policy/`, `internal/store/`, Web Console)**: Layered `RiskPatternRule` evaluation (`global -> env -> system -> target` monotonic inheritance) with 8 composable matchers, 11 preset rule packs (`pg-side-effect`, `sqlite-pragma-blob`, `redis-single-thread`, `mongo-js-explain`, `mysql-dos-guard`, `clickhouse-heavy-scan`, `mssql-proc-dos`, `oracle-sys-guard`, `dameng-sys-guard`, `tdengine-tsdb-guard`, `es-unbounded-scan`), offline dry-run sandbox testing, and structured `MatchedRule` secondary confirmation on CLI and Web approval cards. Remaining planner blind-spot mitigation (`WITH RECURSIVE`, `CONNECT BY`, constant-row functions) relies on explicit classifier rules and user-configured pattern rules above static `EXPLAIN`.
