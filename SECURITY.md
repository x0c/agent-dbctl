# Security Policy

## Local Execution & Data Handling

- **100% Local Execution**: `agent-dbctl` runs locally as a single Go binary with an embedded Web Console bound exclusively to loopback (`127.0.0.1`). Zero telemetry, cloud accounts, or analytics endpoints are contacted.
- **Credential & Webhook Hardening**: Passwords and SSH bastion keys live in your OS Keychain (`keychain` backend on macOS, validating `-s`/`-a` identifiers before `security -i` stdin formatting), environment variables (`env_ref`), or shell-free quote-aware external commands (`exec_provider`, 64 KiB stdout cap, no secret echo on errors)—never inside the SQLite catalog or CLI stdout. Remote webhook approval endpoints require `https://` (`http://` is limited to loopback), sign payloads with HMAC-SHA256 when configured, and omit one-time approval tokens from webhook notifications.
- **Private Storage & Append-Only Audit**: The config directory (`0700`) and SQLite database (explicitly `0600` on Unix) isolate local state; `audit_logs` is append-only with a SHA-256 hash chain and multi-engine credential/literal redaction, while query result payloads remain in a bounded in-memory `ResultSlot` cache (64 slots / 32 MiB) rather than SQLite.
- **Companion Skill Safety**: `agent-dbctl` syncs only its own `agent-dbctl/SKILL.md` into detected local coding-agent skill directories (`~/.claude/skills`, `~/.codex/skills`, `~/.cursor/skills`, `~/.config/opencode/skills`, `~/.agents/skills`, etc.), tracks ownership by SHA-256 in `<config_home>/skills/registrations.json`, refuses symlinks, preserves locally edited files unless `--force` is given, and can be disabled with `AGENT_DBCTL_NO_SKILL_SYNC=1`.

## Trust Boundary

- **CLI vs Human Approval Separation**: Coding agents and engineers can manage authorized catalog entries, topology bundles, instance discovery, security guardrails, and custom risk pattern rules via the `agent-dbctl` CLI over either the private `0600` local daemon RPC channel (`Unix` domain socket on macOS/Linux, `0600` loopback token on Windows) or an authenticated HTTPS remote context. Execution approval decisions (`approve` / `reject`) are strictly excluded from CLI/RPC and from `agent_token` principals, requiring human confirmation in the Web Console or an external `ApprovalProvider` (with four-eyes self-approval prevention enabled by default in server mode).
- **Hardened Local & Server Web Console**: In local mode, `/api/v1/*` validates loopback `Host` headers (`127.0.0.1`, `localhost`, `[::1]`) against DNS rebinding. In server mode, `WebSecurityMiddleware` enforces configured `public_url` / `allowed_hosts`, OIDC or Argon2id authenticated DB-backed sessions (`Secure; HttpOnly`), strict browser same-origin checks (`Origin`/`Sec-Fetch-Site`/`Referer`), and per-session `X-Agent-DBCTL-CSRF` headers. Remote approval deep links (`?token=`) additionally verify authenticated human `approver` RBAC permissions on the target system and environment.
- **Server-Side Secret & RCE Hardening**: Remote server mode encrypts stored secrets using AES-256-GCM envelope encryption (`EncryptedStore` with an external KEK, never plaintext in SQLite/PostgreSQL), and restricts `exec_provider` and `env_ref` credential creation to `platform_admin` principals matching configured `allowed_exec_prefixes` / `allowed_env_prefixes` allowlists.
- **Zero-Secret Web Handoff**: Agents can register managed credentials with a blank secret via CLI and open `ui open --credential <name-or-id>` (or `--open-secret`) so humans enter passwords directly in the local or remote Web UI without ever exposing secrets to the agent or CLI history. Production safety depends on assigning databases to `guarded` (`staging`) or `strict` (`prod`) environments and configuring separate read-only (`ro_credential_id`) vs read-write (`rw_credential_id`) credentials.

## Reporting a Vulnerability

Please report suspected security vulnerabilities privately through GitHub's private vulnerability reporting on `https://github.com/x0c/agent-dbctl/security/advisories/new`. Do not open public issues for unpatched security bugs.
